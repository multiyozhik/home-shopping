# HomeShopping

`HomeShopping` - проект маркетплейса с использованием микросервисной архитектуры:

- микросервис `Catalog` - каталог товаров с поддержкой брендов, категорий и элементов каталога,
- микросервис `Basket` - управление корзиной пользователя (сохранение, получение, удаление, формирование заказа),
- микросервис `Promotion` - управление промоакциями для товаров каталога (CRUD по скидкам: создание, получение, обновление, удаление),
- микросервис `Checkout` - управление заказами (создание, обновление, хранение, получение и удаление заказов).

Разработано на принципах Clean Architecture - чёткое разделение логики на слои со строго направленными зависимостями (Domain не зависит ни от кого, Application зависит от Domain, Infrastructure зависит от Application, а API зависит от Application и Infrastructure).

Стек: 
- C#, ASP.NET Core, gRPC (Promotion), Carter (htttp-маршрутизация в Basket).
- CQRS-паттерн (разделение Commands и Queries) и MediatR.
- Интеграции с брокером сообщений RabbitMQ посредством MassTransit.
- Для работы с данными: PostgresSQL и EF Core, и MySql и Dapper (в Promotion).
- Для маппинга моделей - Mapster.
- Логирование с применением Serilog с конфигурацией для записи в файл и консоль, а также интеграцией с ElasticSearch (конфигурация в appsettings).
- Swagger - для документации API и тестирования.


## Микросервис Catalog


- `Catalog.API` - REST API, контроллеры и DTO-модели, используется `MediatR` для передачи команд и запросов в слой `Application`, реализовано версионирование API v1 и v2 - с помощью `ASP.NET Core Versioning`, а также пагинация с ограничением максимального размера страницы каталога товаров и фильтрация по бренду, категории, и поиском по названию.
- `Catalog.Application` - бизнес-логика, `Models`, `Queries`, `Handlers`, `Responses` для реализации CQRS-паттерна с их маршрутизацией через `MediatR`, используются интерфейсы репозиториев из `Domain`, маппинг через `Mapster`-библиотеку.
- `Catalog.Infrastructure` - репозиторий каталога, реализующий интерфейсы из `Domain` для работы с БД `PostgreSQL` через `Marten`, инициализация базы и загрузка seed-данных.
- `Catalog.Domain` - домен содержит сущности `Brand`, `Category`, `CatalogItem`, интерфейсы репозиториев, `Specifications` для выполнения пагинации и фильтрации товаров в каталоге.


## Микросервис корзины Basket

- Реализовано как `Minimal API` (без контроллеров) в одном сервисе.
- `Carter` - библиотека для http-маршрутизации.
- `CQRS`-паттерн с их маршрутизацией через `MediatR`.
- `Infrastructure`-папка - содержит интерфейс и репозиторий корзины, а также репозиторий кеша корзины в Redis.
- `Models`-папка - модели корзины и элемента корзины.
- `ShoppingBasket`-папка - с папками по командам и запросам для реализации CQRS:
	- `Save` - сохранение корзины с учетом промоакций из Promotion-микросервиса, 
	- `Retrieve` - получение корзины пользователя по accountName, 
	- `Remove` - удаление корзины, 
	- `Checkout` - формирование заказа с `Publish` через `RabbitMQ`/`MassTransit` для Checkout-микросервиса, вызов к которому через gRPC.
- Валидация с `FluentValidation` - для проверки данных для команд и запросов.


## Микросервис Promotion

- Реализован на базе gRPC API в одном проекте.
- `Protos`-папка - контракты gRPC-сервиса (request, response, model, rpc-сервисы).
- `Services`-папка - реализация gRPC методов с маршрутизацией вызова через MediatR.
- `UseCases`-папка - бизнес-логика по сценариям (создание, получение, обновление, удаление промоакций), в каждом кейсе - command или query, handler для реализации CQRS-паттерна.
- `Domain`-папка - с моделью промоакций.
- `Persistence`-папка - интерфейс и репозиторий промоакций с реализацией через Dapper, заполнение seed-данными БД MySql.
- `Interceptors`-папка - RequestLoggingInterceptor для перехвата для обработки gRPC-запросов на стороне сервиса для логирования времени ответа.
- `Configuration`-папка  - для настройки библиотеки Mapster для маппинга протобуферных объектов к доменной модели и обратно.


## Микросервис Checkout

- `Checkout.API` - REST API, реализован `CQRS`-паттерн через `MediatR`, в `Orders`-папке по CRUD-операциям `request`, `response`, `endpoint` с использованием `Carter` - библиотеки для http-маршрутизации.
- `Checkout.Application` - обработчики MediatR для команд и запросов, DTO для передачи данных, валидация моделей с `FluentValidation`, маппинг Mapster.
- `Checkout.Infrastructure` - реализует репозиторий заказов, работу с данными через EF Core (`OrderContext`, миграции), инициализацию данных (seed) для БД `PostgreSQL`, а также интеграцию с `RabbitMQ`/`MassTransit`, определен consumer для делегирования обработки события формирования заказа.
- `Checkout.Domain` - содержит модели для заказов (`Order`, `OrderItem`, `Contact`, `Address`, `CardDetails`) и интерфейсы репозиториев.


## Shared-библиотеки

- `Common.Kernel` - базовые обобщенные интерфейсы CQRS и поведение валидации `ValidationBehavior` для проверки валидности команд, типовые обработки ошибок `CustomExceptionHandler` и исключения `NotFoundException`.
- `Common.Messaging` - интеграция с брокером сообщений RabbitMQ через `MassTransit`, базовое событие и событие формирования заказа, модель для интеграционных событий (сообщений).
- `Common.Logging`  - логирование `Serilog` с поддержкой `ElasticSearch`, файлов, консоли.
- `Common.Metrics` - настройка метрик Prometheus для мониторинга HTTP-запросов.
